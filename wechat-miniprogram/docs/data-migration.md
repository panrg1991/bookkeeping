# 数据存放位置与换手机迁移

## 一、小程序本地存储在哪？（结论：不是文件，无法直接复制）

本地模式的数据用的是微信小程序的 **Storage（键值存储）**，由微信客户端自己管理：

| 平台 | 实际位置 | 能否访问 |
| --- | --- | --- |
| Android | 微信 App 沙箱目录内（`/data/data/com.tencent.mm/...` 下的 appbrand 存储区） | ❌ 未 root 无法访问 |
| iOS | 微信 App 沙箱目录内 | ❌ 未越狱无法访问 |
| 开发者工具（PC） | 工具的本地缓存里，可用「调试器 → Storage」面板查看与修改 | ✅ 仅开发者工具内可见 |

也就是说：**没有 `records.json`、`bookkeeping.db` 这类可以直接拷走的文件**。数据与「当前设备 + 当前微信账号 + 当前小程序」绑定。

在开发者工具里可以这样查看：

> 微信开发者工具 → 调试器 → **Storage** 面板 → 能看到 `bk:records`（记账数据）、`bk:categories`（分类字典）、`bk:seq`（自增 ID）、`bk:logs`（操作日志）。

### 与 PC（Web 版）的对比

| | Web 版（PC） | 小程序本地模式 | 小程序云开发模式 |
| --- | --- | --- | --- |
| 数据形态 | **真实文件** `data/bookkeeping.db`（SQLite） | 微信客户端 Storage（键值） | 云数据库集合 |
| 迁移方式 | 直接复制 `.db` 文件即可 | 备份文本 / 云模式同步 | 自动同步，无需迁移 |
| 换设备 | 拷文件 | 见第二节 | 登录同一微信自动同步 |

> PC 版备份：把项目下 `data/bookkeeping.db` 复制一份即可（也可用 `DB_PATH` 环境变量指向别处）。

## 二、换手机怎么把数据搬过去

三种方式，按推荐度排序：

| 方式 | 是否自动 | 能带走什么 | 适合场景 |
| --- | --- | --- | --- |
| **A. 切云开发模式** | ✅ 自动同步 | 全部数据 | 长期使用、多设备（最优） |
| **B. 备份 / 恢复（JSON 文本）** | 手动搬运一次 | 全部记录 + 分类字典 | 一次性换机（**推荐**） |
| C. 导出 CSV / 批量导入 | 手动搬运 | 仅记录，且只含当前筛选范围 | 少量数据、要与 Excel 交互 |

### 方式 A：切回云开发模式（唯一自动同步）

数据存到云端后，换手机只要登录同一微信账号，打开小程序即可看到全部数据。

1. `utils/config.js` 把 `mode` 改成 `'cloud'`
2. 填 `envId`、部署云函数 `bookkeeping`、执行一次 `initDb` 建集合，并配置集合权限

详见 [cloud-database.md](cloud-database.md) 与 [deploy-checklist.md](deploy-checklist.md) 第四节。

### 方式 B：备份 → 恢复（推荐，已内置功能）

**旧手机（导出）**

1. 打开小程序 →「流水记录」→ 右上角「备份/恢复」
2. 点「**备份数据（复制到剪贴板）**」—— 全部记录 + 分类字典会被复制为一段 JSON 文本，完成后会提示条数与大小
3. 把剪贴板内容**粘贴发送给自己**（推荐发给「文件传输助手」；也可存到备忘录 / 微信收藏）

**新手机（导入）**

1. 用**同一个微信**登录新手机 → 打开小程序 →「流水记录」→「备份/恢复」
2. 把刚才那段 JSON **粘贴**到文本框
3. 点「**覆盖恢复**」（新手机为空时用这个）或「合并恢复」（保留新手机上已有记录、按 id 去重）
4. 回到列表核对条数，并可到「操作日志」页确认有一条 `restore` 记录

备份内容与限制：

| 项目 | 说明 |
| --- | --- |
| 包含 | 全部记录（日期、类型、金额、单价、数量、分类、备注、id、时间戳）+ 分类字典 |
| 不包含 | 操作日志（`bk:logs`，仅用于本机排查，无需迁移） |
| 覆盖恢复 | **先清空当前记录再写入**，不可撤销，操作前会二次确认 |
| 合并恢复 | 保留现有记录，按 id 去重，重复的会跳过（适合两台设备互相同步） |
| 数据量 | 3 条记录约 0.8KB，1000 条约 260KB。剪贴板对超长文本可能有限制，**记录数很大时建议改用方式 A（云模式）或按年份分批备份** |
| 安全性 | 备份文本等同于你的账目数据，发送时只发给自己，不要发到群聊 |

### 方式 C：导出 CSV → 批量导入

「导出 CSV」导出的是**当前筛选条件下**的记录（当前选中的年月，切到「全年」则是该年），所以迁走全部数据需要逐年导出再逐年导入，比较麻烦 —— 因此换机推荐用方式 B。

若只是想把某段时间的数据给到另一台设备，可以：

1. 旧手机：「流水记录」筛好范围 → 「导出 CSV」→ 粘贴发送给自己
2. 新手机：「批量导入」→ 粘贴 CSV → 确认导入

## 三、常见问题

| 问题 | 说明 |
| --- | --- |
| 换手机登录微信后，小程序数据还在吗？ | **不在**。本地模式数据存在旧手机里，不会自动跟随微信账号 |
| 微信自带的「聊天记录迁移」会带上小程序数据吗？ | 不会。它只迁移聊天记录，不含小程序 Storage |
| 卸载微信 / 清缓存 / 删除小程序后会怎样？ | 本地数据会被清除，不可恢复 |
| 换个微信号打开，能看到数据吗？ | 不能。数据按设备 + 微信账号隔离 |
| 能把数据导出成一个文件发出去吗？ | 本地存储本身导不出文件；请用「备份/恢复」把 JSON 文本发给自己，或改用云模式 |
| 备份文本很长，能分次吗？ | 可以按年份分批：先备份全部，再只保留某年的 records 后恢复；更省事的做法是切云模式 |
| PC 版的数据怎么备份？ | 复制 `data/bookkeeping.db` 文件即可；跨电脑搬移时把它放回 `data/` 目录 |

## 四、建议

1. **长期使用**：切到云开发模式（自动多端同步 + 云端留存），本地模式更适合单设备使用或试用
2. **定期留档**：每月用「备份数据」把 JSON 发一份到自己的「文件传输助手」，或导出 CSV 存到电脑
3. **换机前**：先做一次备份并确认能在新手机上恢复成功，再清理旧手机
