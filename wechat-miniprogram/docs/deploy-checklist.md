# 部署配置清单（从开发者工具打开项目 → 可以发布）

本文是「打开项目后到底要配哪些东西」的逐项清单。

## 〇、当前数据模式：本地存储（`mode: 'local'`）

小程序当前使用**本地存储模式**，云开发已暂时停用（云函数代码仍保留在 `cloudfunctions/`，随时可切回）。

| 模式 | 开关 | 数据位置 | 需要云开发 |
| --- | --- | --- | --- |
| **本地存储（当前）** | `utils/config.js` → `mode: 'local'` | 手机本地存储 | **不需要** |
| 云开发数据库 | `utils/config.js` → `mode: 'cloud'` | 微信云开发数据库（多端同步） | 需要开通 + 部署云函数 |

切换只需改 `mode` 一个字段，页面代码不用动（详见第五节）。

## 一、本地模式下需要配置什么

| # | 配置项 | 位置 | 是否必须 |
| --- | --- | --- | --- |
| 1 | `appid` 换成自己的 AppID | `project.config.json` | **发布必须**；本地预览可用游客模式 `touristappid` |
| 2 | 数据模式确认为 `local` | `utils/config.js` 的 `mode` | 默认已是 `local`，无需改动 |

**本地模式下不需要做的事**（与云开发时不同）：

| 事项 | 是否需要 |
| --- | --- |
| 开通云开发环境 | ❌ 不需要 |
| 填写 `envId` | ❌ 不需要（仅云模式使用） |
| 部署云函数 `bookkeeping` | ❌ 不需要 |
| 创建 `records` / `logs` / `settings` 集合 | ❌ 不需要 |
| 配置集合安全规则与索引 | ❌ 不需要 |
| 配置 openid / AppSecret | ❌ 不需要，且**没有任何可配置的地方**（见第六节） |
| 配置服务器域名、HTTPS、备案 | ❌ 不需要 |

**小程序端与云开发相关的代码已自动跳过**：`app.js` 只在 `mode === 'cloud'` 时才调用 `wx.cloud.init()`。

## 二、本地模式的运行步骤（3 步）

1. 微信开发者工具 → 导入项目 → 目录选 `wechat-miniprogram`
2. AppID 填自己的（仅本地预览也可用「测试号」或游客模式）
3. 编译运行 —— 完成，无需任何服务器配置

首次运行会自带一套默认分类（餐饮 / 交通 / 工资…），直接记一笔即可。

## 三、数据存储说明（本地模式）

| 存储键 | 内容 |
| --- | --- |
| `bk:records` | 记账数据 |
| `bk:categories` | 分类字典 |
| `bk:seq` | 自增 ID |
| `bk:logs` | 操作日志（滚动保留最近 500 条） |

- 数据只在**当前设备 + 当前微信账号**，换设备不同步
- 开发者工具「清缓存」或用户删除小程序会清空数据，建议定期用「导出 CSV」留档
- 操作日志仍完整记录（新增 / 修改 / 删除 / 导入 / 失败），可在「流水记录 → 操作日志」查看；日志页顶部会显示「数据模式：本地存储（仅本机）」

## 四、切回云开发模式的步骤

改 `utils/config.js`：

```js
module.exports = {
  mode: 'cloud',                          // ← 从 'local' 改成 'cloud'
  envId: 'bookkeeping-1g2h3i4j5k6l',      // ← 填云开发环境 ID
  ...
};
```

然后完成云开发部署（与之前相同）：

1. 顶部「云开发」→ 开通环境 → 复制环境 ID 填入 `envId`
2. `cloudfunctions/bookkeeping` 右键 →「**上传并部署：云端安装依赖**」
3. 云开发控制台 → 云函数 → `bookkeeping` → 云端测试 → `{ "action": "initDb" }` 执行一次，创建三个集合
4. 三个集合安全规则设为 `{"read": false, "write": false}`，并按需建索引

细节见 [cloud-database.md](cloud-database.md)。

> 注意：两种模式的数据**互不相通**。从本地切到云端后是空数据，需要重新录入或导入（可先在本地模式导出 CSV，切到云模式后用「批量导入」粘贴导入）。

## 五、两种模式对比

| 项目 | 本地存储（当前） | 云开发数据库 |
| --- | --- | --- |
| 数据位置 | 手机本地 | 云数据库 |
| 多端同步 | ❌ | ✅ 同一微信账号自动同步 |
| 数据隔离 | 按设备 + 微信账号 | 按 openid |
| 需要云环境 | 不需要 | 需要开通 + 部署云函数 |
| 需要真实 AppID | 发布时需要 | **是**（游客模式无法用云开发） |
| 操作日志 | 本地保存（上限 500 条） | 云端 `logs` 集合（无上限，可清理） |
| 容量 | 本地存储约 10MB（约 6000 条记录 + 日志） | 云开发配额（远大于本地） |
| 适合场景 | 单设备自用、先跑起来 | 多端同步、长期使用、需要审计日志 |

## 六、关于 openid：当前模式不需要，云端模式也不用配置

- **本地模式**：没有用户体系，数据直接存在本机，压根不涉及 openid
- **云端模式**：openid 由微信在调用云函数时自动注入（`cloud.getWXContext().OPENID`），云函数自动写入数据的 `_openid` 字段 —— **同样不需要在代码或配置里填任何 openid**，也**不需要 AppSecret**

只有在「改造成自建后端」时才需要 AppSecret（服务端用 `code` 换 openid，且 AppSecret 绝不能放进小程序代码）。

日志页顶部可查看当前身份：本地模式显示「本地模式（未接入云开发）」，云端模式显示脱敏 openid（点击可复制完整值）。

## 七、常见报错 → 缺了哪一步

| 现象 / 报错 | 原因 | 处理 |
| --- | --- | --- |
| 打开就弹「云环境未就绪」 | 把 `mode` 设成了 `cloud` 但云环境未部署 | 改回 `mode: 'local'`，或按第四节完成云开发部署 |
| 「云函数 bookkeeping 未部署」 | 同上 | 同上 |
| 「collection not exists」 | 云端模式但集合未创建 | 执行 `initDb` |
| 上传代码报 AppID 校验失败 | 还是 `touristappid` | 换成真实 AppID |
| 换了手机数据没了 | 本地模式数据不跨设备 | 属正常；需要同步就切云端模式 |
| 清缓存后数据消失 | 本地存储随缓存清除 | 属正常；定期「导出 CSV」留档 |
| 日志只保留 500 条 | 本地日志滚动上限 | 属正常；云端模式无此限制 |

## 八、发布前检查

| 检查项 | 通过标准 |
| --- | --- |
| `project.config.json` 的 `appid` | 是自己的真实 AppID（`touristappid` 无法上传） |
| `utils/config.js` 的 `mode` | 与预期一致（当前为 `local`） |
| 功能自测 | 增删改查、导入、导出、统计、操作日志均正常 |
| 空数据风险 | 首次进入无数据，审核备注需写清体验路径（模板见 [release.md](release.md)） |
| 隐私声明 | 本地模式：数据仅存手机本地；云端模式：数据存于微信云开发、仅本人可见 |

## 九、可选配置

| 目的 | 怎么做 |
| --- | --- |
| 导入大量数据时少写日志 | `store.importRecords(items, { detailLog: false })`（`pages/records/index.js`） |
| 调整本地日志保留条数 | `utils/store.local.js` 顶部的 `MAX_LOGS`（默认 500） |
| 需要审计「谁在什么时候查了数据」 | 云端模式：云函数 `index.js` 里 `LOG_READS` 改为 `true` |
| 彻底删除云开发相关文件 | 删除 `cloudfunctions/` 目录，并移除 `project.config.json` 里的 `cloudfunctionRoot` 字段 |
