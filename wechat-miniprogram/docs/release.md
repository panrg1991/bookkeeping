# 小程序发布上线指引

## 一、先回答：只提供 AppID 和 key 就能直接发布吗？

**不能。** 发布这件事，AppID 和密钥都不是"替别人发布"的凭据，三者用途完全不同：

| 名称 | 是什么 | 用在哪 | 本小程序是否需要 |
| --- | --- | --- | --- |
| **AppID** | 小程序唯一身份标识（如 `wx1234567890abcdef`） | 开发者工具项目配置、上传、云开发 | **必须** |
| **AppSecret**（密钥） | 服务端调用微信开放接口的凭据（换 openid、access_token 等） | **只能放在你自己的服务端** | **不需要**（本项目无服务端） |
| **代码上传密钥** | 后台生成的 `.key` 文件，供 `miniprogram-ci` 命令行/CI 自动上传 | 自动化上传 | 可选，仅做 CI 时才要 |

关键结论：

1. **AppSecret 不能用来发布**，而且**绝对不能写进小程序前端代码**（代码包可被反编译，密钥泄露会被他人冒用调用接口）。本小程序不调用任何微信服务端接口，因此完全不需要 AppSecret。
2. **上传代码**靠的是「微信开发者工具登录的微信号 + 该微信号已被添加为该小程序的开发者/管理员」，不是密钥。
3. **提交审核和发布**必须在 `mp.weixin.qq.com` 后台由管理员手动完成（或通过第三方平台代发布）。也就是说：**发布只能由持有该小程序账号的管理员来做**，别人拿到 AppID 也无法代你发布。

> 如果你是想让我（或其他人）帮你完成发布：无法代做，因为需要你的微信扫码登录后台与开发者工具。我能做的是把代码准备好、把 appid 换好、并给出每一步的操作清单（即本文）。

## 二、发布前的准备清单

| 事项 | 说明 | 本项目情况 |
| --- | --- | --- |
| 注册小程序账号 | `mp.weixin.qq.com` → 注册 → 小程序，个人/企业主体均可 | 需要 |
| 主体认证 | 个人：身份证 + 人脸核身；企业：对公打款或微信认证（约 300 元/年） | 需要 |
| 小程序名称 / 头像 / 简介 | 后台「设置 → 基本设置」填写，名称需唯一且不含敏感词 | 需要 |
| 服务类目 | 后台「设置 → 基本设置 → 服务类目」 | 需要，见下方注意 |
| 管理员与开发者 | 「成员管理」把自己的微信号设为管理员/开发者 | 需要 |
| 服务器域名（request 合法域名） | 需要 HTTPS + 已备案域名 | **不需要**（本项目零网络请求） |
| 云开发环境 | 需要开通并配置 env | **不需要**（数据存本地） |
| 《用户隐私保护指引》 | 使用隐私接口时必须在后台声明 | **基本不需要**，见下方注意 |
| 代码上传 | 微信开发者工具「上传」 | 需要，AppID 必须换成真实 AppID |
| 提交审核 → 发布 | 后台「版本管理 → 开发版本 → 提交审核 → 发布」 | 需要 |

### 类目注意

- 建议选择 **「工具 → 效率」** 一类**无需特殊资质**的类目。
- 尽量不要选金融 / 财会类目（如"金融信息""财会服务"），这类通常要求《金融许可证》《代理记账许可证》等资质，个人主体无法提供，会导致审核不通过。

### 隐私注意

本小程序只用了：

- 小程序本地存储（存记账数据，不离开手机）
- `wx.setClipboardData`（把 CSV 写入剪贴板）

**没有**调用获取头像昵称、手机号、位置、相册、通讯录、剪贴板读取等需要用户授权的隐私接口，因此一般不会触发隐私授权弹窗。若后台要求补充《用户隐私保护指引》，按最小化原则填写，例如："本小程序为本地记账工具，数据仅保存在用户手机本地，不上传、不共享。"

## 三、本项目"零配置"的优势

| 常见发布门槛 | 本项目 |
| --- | --- |
| 服务器域名 + ICP 备案 | 不需要（无任何网络请求） |
| HTTPS 证书 | 不需要 |
| 云开发环境 / 数据库配置 | 不需要（数据存本地存储） |
| 第三方 npm 依赖与构建 | 无依赖、无构建，包体仅几十 KB（主包上限 2MB 毫无压力） |
| 隐私接口声明 | 未使用隐私接口 |

## 四、完整发布步骤

### 1. 注册并完善后台信息

1. `mp.weixin.qq.com` → 「立即注册」→ 选择「小程序」
2. 用邮箱注册 → 激活 → 选择主体类型并完成认证
3. 登录后台 → 「设置 → 基本设置」填写名称、头像、简介、服务类目
4. 「成员管理」把自己的微信号加为管理员/开发者

### 2. 拿到 AppID 并替换到工程里

后台「设置 → 基本设置 → 账号信息」可看到 `AppID`。把本目录 `project.config.json` 里的游客模式 AppID 换掉：

```json
{
  "appid": "touristappid"   // ← 改成你的真实 AppID，如 wx1234567890abcdef
}
```

> `touristappid` 是游客模式，只能本地预览，**无法上传与发布**，必须替换。

### 3. 用开发者工具上传

1. 微信开发者工具 → 导入项目 → 选择 `wechat-miniprogram` 目录
2. 右上角「上传」→ 填写**版本号**（如 `1.0.0`）与**项目备注**（如"首次发布：本地记账统计"）
3. 上传成功后，代码进入后台「版本管理 → 开发版本」

上传前建议自测一遍：`月度总览` / `每日明细` / `流水记录` / `分类统计` 四个页面，以及新增、修改、删除、批量导入、导出 CSV。

### 4. 设为体验版给朋友或自己试（可选）

后台「版本管理 → 开发版本 → 选为体验版」，然后在「成员管理 → 体验成员」添加微信号（个人主体上限较少）。扫码即可在真机体验，不影响后续审核。

### 5. 提交审核

1. 后台「版本管理 → 开发版本」→ 对应版本右侧「提交审核」
2. 填写功能页面、测试账号（本项目无需登录，可留空）
3. **审核备注建议这样写**（重要，见第六节的空数据问题）：

```
本小程序为纯本地记账工具，无需登录、无网络请求、数据仅保存在手机本地。
审核路径：底部「流水记录」→ 选择日期/类型，输入金额与分类 → 点「保存记录」；
随后在「月度总览」查看各月收支与利润统计，「每日明细」点击任意日期可展开当天流水并修改/删除，
「分类统计」查看各分类占比。首次进入时无数据属正常现象。
```

### 6. 发布

审核通过后，后台「版本管理 → 审核版本 → 发布」：

- **全量发布**：所有用户立即可用
- **灰度发布**：先放 5%~100% 的流量，观察后再全量（个人主体一般可直接全量）

### 7. 后续更新

改完代码 → 开发者工具「上传」（版本号递增，如 `1.0.1`）→ 后台提交审核 → 发布。已发布版本不受影响，审核期间线上仍是旧版本。

## 五、三个"密钥/标识"的区别与安全红线

```
AppID                  → 写进 project.config.json，公开信息，不敏感
AppSecret              → 只放服务端！前端出现即视为泄露，需立刻在后台重置
代码上传密钥(private.key) → 只放本地/CI，务必加入 .gitignore，不要提交到 Git
```

- 本项目**不需要 AppSecret**：没有登录换 openid、没有消息推送、没有服务端调用。
- 若将来接入「用户 openid」实现多端同步，正确做法是：小程序 `wx.login` 拿到 `code` → 传给自己的服务端 → 服务端用 `AppID + AppSecret + code` 换 `openid`。**AppSecret 永远不出现在小程序代码里。**
- 若用微信云开发，则不需要自己保管 AppSecret，云函数里 `cloud.getWXContext()` 即可拿到 openid。

## 六、审核前自检清单

| 检查项 | 说明 |
| --- | --- |
| AppID 已替换 | `project.config.json` 不再是 `touristappid` |
| 基础信息完整 | 名称、头像、简介、服务类目已填 |
| **首次打开是空数据** | 本应用无内置示例数据，审核员可能看到空页面而认为"功能不完整"。**务必在审核备注里写清操作路径**（见第 4 节第 5 步的模板） |
| 无报错弹窗 | 真机预览走一遍增删改查，确认无 `wx.showToast` 报错 |
| 无 TODO / 测试文案 | 页面文案为正式中文表述 |
| 包体大小 | 主包 < 2MB（当前远小于限制） |
| 无未使用的权限声明 | `app.json` 中没有多余的 `permission` / `requiredPrivateInfos` 配置 |
| 剪贴板提示 | 「导出 CSV」会写剪贴板，系统会自动提示"内容已复制"，属正常行为 |

> 若希望避免"空数据"带来的审核风险，可以在小程序里加一个「载入示例数据」入口（一行 `store.importRecords(...)` 即可），首次进入时展示。需要的话可以补上。

## 七、需要 CI 自动化上传时（可选）

只有在"每次提交代码自动上传开发版"时才需要这一步。仍然**不能自动提交审核与发布**。

```bash
npm i -D miniprogram-ci
```

后台「开发管理 → 开发设置 → 小程序代码上传」生成密钥并下载 `private.<appid>.key`，同时配置 IP 白名单。

```js
// upload.js
const ci = require('miniprogram-ci');

const project = new ci.Project({
  appid: 'wx1234567890abcdef',
  type: 'miniProgram',
  projectPath: './wechat-miniprogram',
  privateKeyPath: './private.wx1234567890abcdef.key',
  ignores: ['node_modules/**/*', 'docs/**/*'],
});

ci.upload({
  project,
  version: '1.0.1',
  desc: '自动化上传',
  setting: { es6: true, minify: true },
}).then((res) => console.log('上传成功', res)).catch((err) => console.error('上传失败', err));
```

上传完成后仍需到后台手动「提交审核 → 发布」。

## 八、常见驳回原因与处理

| 驳回提示 | 原因 | 处理 |
| --- | --- | --- |
| 服务类目与实际功能不符 | 类目选了金融/财会，或功能超出类目 | 改成「工具 → 效率」等匹配类目 |
| 功能不完整 / 页面空白 | 首次进入无数据，审核员看不到功能 | 在审核备注写清操作路径，或加入"载入示例数据"入口 |
| 需要补充资质 | 类目要求许可证 | 更换为无需资质的类目 |
| 涉及用户隐私而未声明 | 后台未填写隐私保护指引 | 后台按最小化原则补充声明 |
| 小程序名称不合规 | 名称含"金融""投资"等敏感词或与已有重名 | 更换名称 |
| 存在测试内容 / 调试开关 | 页面留有测试文案 | 清理后重新上传 |

## 九、如果以后要接后端 / 云开发

一旦开始发起网络请求，发布门槛会明显增加，需要额外做：

1. 准备 **HTTPS** 域名，并完成 **ICP 备案**
2. 后台「开发管理 → 开发设置 → 服务器域名」配置 `request` 合法域名
3. 若使用云开发：开通环境、配置 `env`、部署云函数
4. 若采集用户信息：在后台填写《用户隐私保护指引》并在代码中处理隐私授权

这些改造方式见 [data-and-api.md](data-and-api.md) 第五节。
